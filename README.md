# Dex PMS

**Web-Based Project Management System with Decision Support**
Internal tool for Dex International Co. — elevator and crane installation, maintenance, and servicing projects.

## Quick Start: One-Command Automated Setup

### Prerequisites
1. **Docker Desktop** — running on your PC (download from [docker.com](https://www.docker.com/products/docker-desktop/)).
2. **Git** — to clone the repository.

### Run on a New PC (Windows PowerShell)
```powershell
# 1. Clone the repository
git clone https://github.com/HarryCantCode/capstone-project-management-decision-support.git
cd capstone-project-management-decision-support

# 2. Run the automated setup script
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

### Run on a New PC (Linux / macOS / WSL2 Bash)
```bash
# 1. Clone the repository
git clone https://github.com/HarryCantCode/capstone-project-management-decision-support.git
cd capstone-project-management-decision-support

# 2. Run the automated setup script
chmod +x setup.sh
./setup.sh
```

The automated script handles:
- Checking Docker status
- Generating `.env` from `.env.example`
- Bootstrapping Composer packages via a temporary Docker container (no PHP needed on the host PC)
- Launching all Docker containers (`laravel.test`, `mysql`, `redis`, `phpmyadmin`)
- Generating the Laravel application key
- **Restoring Full Database Data:** Automatically imports `database/seed_data.sql` if present (restoring all existing projects, personnel, accounts, and history). If absent, it falls back to clean migrations and demo seeders.
- Installing Node packages and compiling Vite production assets

Once finished, navigate to **http://localhost** in your browser!

### Syncing Database Data Between PCs
To capture the latest database state (projects, accounts, costs, personnel) from this machine and share it to GitHub:
- **Windows PowerShell:** `powershell -ExecutionPolicy Bypass -File .\export-db.ps1`
- **Linux / macOS / WSL2:** `./export-db.sh`
Then commit and push `database/seed_data.sql` to GitHub. When the second PC runs `setup.ps1` or `setup.sh`, it will automatically load that data!

## Manual Development Setup (Laravel Sail / WSL2)

### Prerequisites

1. **WSL2 with Ubuntu** — install if not already present:
   ```bash
   wsl --install Ubuntu
   ```
   Reboot when prompted. Launch Ubuntu and create your UNIX username/password.

2. **Docker Desktop** — download from [docker.com](https://www.docker.com/products/docker-desktop/).
   After install, open Docker Desktop → Settings → Resources → WSL Integration → enable for Ubuntu.

3. **Git** — must be installed on Windows (already configured if you cloned this repo).

### First-time manual setup (run all commands inside WSL2/Ubuntu terminal)

```bash
# 1. Navigate to the project (Windows filesystem is mounted under /mnt/c)
cd "/mnt/c/MY PROJECTS/Project mangement system - capstone"

# 2. Install PHP dependencies (uses Sail's PHP image for first run)
docker run --rm \
    -u "$(id -u):$(id -g)" \
    -v "$(pwd):/var/www/html" \
    -w /var/www/html \
    laravelsail/php82-composer:latest \
    composer install --ignore-platform-reqs

# 3. Copy and configure the environment file
cp .env.example .env

# 4. Start Sail (builds Docker containers on first run — takes a few minutes)
./vendor/bin/sail up -d

# 5. Generate application key
./vendor/bin/sail artisan key:generate

# 6. Run migrations and seeders
./vendor/bin/sail artisan migrate --seed

# 7. Install front-end dependencies and build assets
./vendor/bin/sail npm install
./vendor/bin/sail npm run dev
```

The application will be available at **http://localhost**.

### Daily development workflow

```bash
# Start containers (from inside WSL2 terminal)
./vendor/bin/sail up -d

# Stop containers
./vendor/bin/sail down

# Run Artisan commands
./vendor/bin/sail artisan <command>

# Run Composer commands
./vendor/bin/sail composer <command>

# Watch assets (hot reload)
./vendor/bin/sail npm run dev
```

### Useful alias (optional — add to ~/.bashrc in Ubuntu)

```bash
alias sail='./vendor/bin/sail'
```

## Required `.env` Variables

Copy `.env.example` to `.env` and fill in these values. **Never commit real credentials.**

| Variable | Description |
|---|---|
| `APP_NAME` | Should be `"Dex PMS"` |
| `APP_KEY` | Generated by `php artisan key:generate` |
| `APP_ENV` | `local` for development, `production` on the server |
| `APP_DEBUG` | `true` for local, **`false` in production** |
| `APP_URL` | `http://localhost` locally; internal hostname in production |
| `DB_CONNECTION` | `mysql` |
| `DB_HOST` | `mysql` (Sail service name) |
| `DB_PORT` | `3306` |
| `DB_DATABASE` | `dex_pms` |
| `DB_USERNAME` | Your MySQL user (never `root` in production) |
| `DB_PASSWORD` | Strong, unique password |
| `SESSION_DRIVER` | `database` |
| `SESSION_LIFETIME` | `120` (minutes — 2-hour idle timeout) |
| `QUEUE_CONNECTION` | `database` |

## Running Migrations

```bash
# Run all pending migrations
./vendor/bin/sail artisan migrate

# Run migrations with seeders (demo data)
./vendor/bin/sail artisan migrate --seed

# Roll back the last migration batch
./vendor/bin/sail artisan migrate:rollback
```

## Running Tests

```bash
# Run the full test suite (always run before merging a branch)
./vendor/bin/sail artisan test

# Run a specific test file
./vendor/bin/sail artisan test tests/Feature/AuthTest.php

# Run with coverage (requires Xdebug or PCOV)
./vendor/bin/sail artisan test --coverage
```

Tests use **Pest**. Do not mix PHPUnit-style tests into this codebase.

## Code Style

This project uses **Laravel Pint** (PSR-12 preset). A pre-commit hook runs Pint automatically.

```bash
# Check for style issues without fixing
./vendor/bin/sail exec laravel.test ./vendor/bin/pint --test

# Auto-fix style issues
./vendor/bin/sail exec laravel.test ./vendor/bin/pint
```

## Roles

| Role | Access |
|---|---|
| **Admin** | Full access: all modules + costing + scheduling + user management |
| **Manager** | Project management, resource allocation, manpower, reports |
| **Inventory Staff** | Resource allocation, equipment records |

Demo seeders create one account per role. Credentials are in `database/seeders/DemoUserSeeder.php`.

## Git Workflow

```
main       ← production-ready tagged releases only
  |
develop    ← integration branch; all feature PRs merge here
  |
feature/*  ← short-lived feature branches (one per module)
```

Commit message format: imperative mood, one logical change per commit.
- ✅ `Add project status transition validation to ProjectService`
- ❌ `fixes` / `wip` / `updates`
